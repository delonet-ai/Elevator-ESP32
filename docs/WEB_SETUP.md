# Веб-настройка сети — первая версия

Используется WiFiManager 2.0.17. Базе нужен Wi-Fi 2,4 ГГц.
Доступны настройка сети, диагностика и [веб-калибровка](WEB_CALIBRATION.md).
Обычные поездки на этажи из браузера пока не добавлены.

## Первое подключение

1. Собрать и обновить **обе** платы: окружения `lift` и `remote`.
   Обновление только базы нарушит работу старого пульта при смене радиоканала.
2. Открыть USB Serial базы на 115200. При запуске выводятся имя точки
   `Lift-Setup-XXXXXX` и индивидуальный пароль. Команда `NETWORK` повторяет данные.
   Не публикуйте журнал с этим паролем.
3. Если сохранённая сеть недоступна или ещё не задана, подключиться телефоном
   к этой точке и открыть `http://192.168.4.1`. Автоматическое открытие портала
   зависит от телефона; ручной адрес работает без интернета.
4. Выбрать сеть, ввести пароль и сохранить. Пока открыт портал, запуск движения
   с пульта и Serial блокируется. STOP не блокируется.
5. Вернуть телефон в домашнюю сеть. Полученный базой IP выводится в Serial
   и доступен в списке клиентов роутера. Открыть `http://<IP>/`.
6. Войти: пользователь `admin`, пароль тот же, что у точки настройки.
   Сетевые реквизиты сохраняет WiFiManager/ESP32; пароль доступа хранится в NVS.

Страница показывает состояние, этаж/цель, шаговую координату, её достоверность,
ошибку, верхний концевик, регулятор скорости, регистрацию пульта, канал и время работы.
«Пульт зарегистрирован» не является проверкой его текущей доступности.
IP выдаётся роутером и может измениться; для постоянного адреса можно настроить
резервирование DHCP на роутере.

Диагностика работает и во время движения. Основной цикл публикует согласованный
снимок каждые 100 мс, браузер запрашивает его раз в секунду. Добавлены признак
движения мотора, измеренный ход, уровень сигнала Wi-Fi и свободная память.
Снимок старше секунды отображается как устаревший, даже если HTTP отвечает.

## Смена сети и восстановление

Кнопка «Настроить другую сеть» требует входа, свежего состояния покоя и
подтверждения. Запрос проходит через ограниченную очередь в основной цикл,
где состояние покоя проверяется повторно. Если лифт успел начать движение
или запрос старше двух секунд, он отклоняется, а не откладывается до остановки.
Принятый запрос останавливает веб-сервер и открывает защищённую точку настройки.
Пароль остаётся прежним.
WiFiManager не публикуется как портал настройки в домашней сети.

Если Wi-Fi потерян, через 15 секунд обслуживания в неподвижном состоянии
открывается точка настройки. Автоматическое сканирование/переподключение во время
движения выключено. Портал не запускается в процессе поездки, хоминга или
калибровки, включая паузу калибровки вниз. Сначала завершите процесс или
переведите автомат в состояние ожидания через штатные команды.

Страница диагностики использует ESPAsyncWebServer 3.6.0 и AsyncTCP 3.3.2;
обработчики HTTP работают с копиями данных и не вызывают функции мотора,
автомата или NVS. Только портал WiFiManager обслуживается в неподвижном
состоянии: его сканирование и подключение могут задерживать основной цикл.
Не используйте веб как аварийный стоп. Авторизация HTTP предназначена
для доверенной локальной сети; порт нельзя открывать в интернет.

GPIO33 пока остаётся кнопкой рекалибровки. Его назначение не изменено.

## Пульт и ESP-NOW

База использует текущий канал роутера/точки доступа; peer с каналом 0 следует
этому каналу. Пульт перебирает каналы 1–13 (регион RU), задерживаясь на каждом
400 мс и посылая только DISCOVER. При свежем статусе поиск прекращается.
После потери статуса более чем на 1,5 с поиск возобновляется. Полный проход
занимает около 5,2 с без учёта потерь пакетов.

Команды движения не отправляются широковещательно и запрещены без свежего
статуса. После потери связи нужно отпустить кнопки, прежде чем снова управлять.
В пределах одного включения пульт сохраняет выбранный MAC базы. Это не
криптографическое сопряжение: для нескольких лифтов рядом потребуется отдельная
процедура привязки. Версия структуры пакетов остаётся 2.

## Проверки

Автоматизированные:

```sh
pio run -e lift -e remote -e lift_bench
node --test tests/web_ui.test.cjs
git diff --check
```

До эксплуатации выполнить на платах (сейчас не подтверждены):

- [ ] Пустые настройки: защищённая AP, портал вручную и через captive portal.
- [ ] Верный/неверный пароль роутера; повторный ввод без зависания контроллера.
- [ ] Перезапуск: сохранены реквизиты и пароль доступа; IP выводится в Serial.
- [ ] Вход в веб без пароля отклоняется; смена сети без токена отклоняется.
- [ ] Смена сети через веб; старый веб-сервер освобождает порт 80.
- [ ] Роутер на каналах 1, 6, 11 и 13: пульт находит базу и получает статусы.
- [ ] Смена канала/перезапуск роутера: повторный поиск; удержанная кнопка не
  вызывает движение после восстановления связи до отпускания и нового нажатия.
- [ ] Портал блокирует все входы движения, STOP остаётся доступным.
- [ ] Во время движения страница обновляет координату/состояние, смена сети
  недоступна. Несколько клиентов и медленный клиент не мешают опросу концевика
  и таймауту ручного удержания; проверить задержки на реальной плате.
- [ ] Между запросом смены сети и его обработкой начинается движение: запрос
  отменяется и не исполняется позже автоматически.
- [ ] Отключение роутера: AP появляется после остановки; накопленные старые
  радиокоманды не запускают движение после обслуживания HTTP/портала.

Прошивки, скомпилированные на компьютере, ещё не означают прохождение этих проверок.

## Архитектура веб-части

- `web_config.cpp`: жизненный цикл сети, WiFiManager, формирование снимков
  и проверка запросов в основном цикле управления.
- `web_dashboard.cpp`: асинхронный HTTP, авторизация, снимки под короткой
  критической секцией и очередь запроса настройки сети.
- `web_page.h`: автономная страница без внешних CDN.
- GitHub Actions запускает тесты страницы и сборки трёх окружений.

Веб-калибровка реализована отдельным модулем `web_calibration.cpp`: очередь
команд, владение сессией и таймаут подтверждений. Подробности — в [инструкции](WEB_CALIBRATION.md).
