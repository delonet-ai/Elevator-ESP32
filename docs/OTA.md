# OTA, имена контроллеров и передача Wi-Fi

Исходники поддерживают обновление базы и пульта через браузер. Первое обновление
обеих плат и привязка выполняются через USB. 11 октября 2026 база обновлена через USB, затем успешно обновлена по Wi-Fi.
На ней проверены вход в режим обслуживания, авторизация, отказ на пакет пульта,
неполный файл и повреждённую SHA256. После OTA сохранились Wi-Fi и калибровка
(ход 36230 шагов), состояние NEED_HOMING, самостоятельного движения не было.
Испытания радиообмена с двумя платами и обрыва питания при записи ещё необходимы.

## Имена в роутере

DHCP hostname базы — `lift-base-XXXXXX`, пульта — `lift-remote-XXXXXX`.
Суффикс — последние три байта STA MAC. Он стабилен после перезапуска и обновления.
База задаёт имя до подключения через WiFiManager. Пульт задаёт имя при запуске,
но появляется в DHCP-клиентах только в режиме Wi-Fi/OTA: ESP-NOW не выдаёт IP.
Роутер может показывать собственный псевдоним или кэшированное имя. Это DHCP,
не mDNS: доступ по `.local` не реализован. Имя точки первичной настройки базы
`Lift-Setup-...` сохраняется. Пароль этой точки фиксирован: `Poiu0987`.
Он отделён от индивидуального пароля веб/OTA; последний сохраняется в NVS
и выводится командой USB `NETWORK` в строке `Dashboard login`.

## Однократная привязка через USB

1. Собрать и прошить окружения `lift` и `remote` обычным USB-способом.
2. Получить STA MAC каждой платы из её загрузочного лога.
3. В неподвижном состоянии записать в каждую плату MAC **другой** платы
   и общий случайный ключ. Один файл ключа используется для обеих команд:

   ```sh
   python tools/pair_device.py --port COM7 --peer AA:BB:CC:DD:EE:FF
   python tools/pair_device.py --port COM8 --peer 11:22:33:44:55:66
   ```

   Адреса и порты в примере заменяются реальными. Обе платы одновременно
   подключать не обязательно. Скрипт создаёт `.private/pair.json`, если файла
   ещё нет. Каталог исключён из Git. Не удаляйте файл между прошивками двух плат
   и не публикуйте его. В терминал ключ не выводится.
4. После подтверждения записи перезапустить обе платы. Настройка хранится
   в NVS `lift-pair`, OTA её не стирает. Смена пары также выполняется через USB.

До привязки обычный поиск пульта остаётся совместимым с прежним протоколом,
но передача Wi-Fi запрещена. После привязки принимается только сохранённый MAC;
unicast ESP-NOW использует LMK/PMK пары. Служебные сообщения дополнительно
проверяются HMAC-SHA256 (16 байт тега). Ответ с реквизитами связан со случайным
16-байтным запросом пульта, действительным менее 3 секунд и используемым один раз.
Это предотвращает повтор старого ответа для перевода пульта в OTA.
Пароли никогда не отправляются broadcast.

## Автоматическая передача настроек

Привязанный пульт в покое, со свежей связью и отпущенными кнопками запрашивает
параметры базы. База отвечает только вне движения, калибровки и портала настройки.
Передаются SSID, пароль роутера и пароль веб-доступа базы. Пульт сохраняет
изменившиеся данные отдельной записью NVS `lift-net`; обычное управление остаётся
на ESP-NOW. После смены сети базы реквизиты синхронизируются снова.

## Обновление из браузера

1. На странице базы нажать «Перейти в OTA: база и пульт». Основной цикл повторно
   проверяет покой, отсутствие калибровки и возраст запроса. После принятия
   новые команды движения блокируются. EN мотора при записи не выключается.
2. База открывает страницу `http://<IP-базы>:8080/`. Привязанному пульту в течение
   минуты предлагается перейти в Wi-Fi. Пульт отключает управление кнопками,
   подключается к тому же роутеру и показывает IP на OLED. После подтверждения
   его адрес появляется на странице базы. Если пульт не подключился, завершить
   режим и повторить после восстановления связи.
3. На обеих страницах вход — `admin`, пароль тот же, что на базе. Выбрать
   соответствующий пакет `.liftota`; отправка защищена токеном сеанса.
4. После проверки длины, SHA256 и образа приложение переключается на новый
   раздел и перезапускается. По окончании работы с пультом режим базы нужно
   завершить кнопкой перезапуска на её OTA-странице, если база не обновлялась.

База не снимает блокировку сама при потере браузера. Пульт возвращается к
обычной работе перезапуском при невозможности подключиться за 20 секунд либо
через 5 минут вне активной загрузки. Повторные команды движения не накапливаются.
После перезапуска базы положение неизвестно; восстановление по верху запускается
отдельной командой. Перезапуск имеет обычные для ESP32 последствия для GPIO;
удержание кабины во время сброса питания должно быть проверено на механике.

## Подготовка пакетов

```sh
pio run -e lift -e remote
python tools/package_ota.py lift
python tools/package_ota.py remote
```

Результаты: `.pio/build/lift/lift.liftota` и `.pio/build/remote/remote.liftota`.
Обычный `firmware.bin`, bootloader, таблица разделов и стендовая прошивка в OTA
не принимаются как пакеты. Упаковщик проверяет встроенную метку типа прошивки;
контроллер проверяет тип в заголовке, размер, контрольную сумму и ESP32-образ.
Не меняйте заголовки пакетов вручную. Контрольная сумма обнаруживает повреждение,
но не является цифровой подписью автора. HTTP рассчитан на доверенную локальную
сеть; этот сервис не предназначен для доступа из интернета.

Используется штатная разметка `default.csv`: два OTA-слота по `0x140000` байт
и `otadata`. Новая прошивка записывается в неактивный слот. При неполной загрузке
или неверной сумме он не выбирается для запуска; настройки NVS сохраняются.
Автоматический откат после загрузки исправного по формату, но неработающего
приложения **не реализован**. Для такого восстановления пока нужен USB.

## Что проверить на двух платах

- Привязку, взаимный поиск по каналам и сохранение ключа после перезапуска.
- Передачу и смену SSID/пароля без вывода секретов в журнал.
- DHCP-имена и переход обоих контроллеров в OTA по одной кнопке.
- Запрет OTA при движении/калибровке и всех команд движения в режиме OTA.
- Неверный тип файла, неполный файл, повреждённую сумму, повторную загрузку.
- Обрыв сети/питания при записи и последующий запуск прежнего приложения.
- Сохранение настроек и отсутствие самостоятельного движения после перезапуска.

Основа: [ESP-NOW security](https://docs.espressif.com/projects/esp-idf/en/v4.4.7/esp32/api-reference/network/esp_now.html)
и [OTA partitions](https://docs.espressif.com/projects/esp-idf/en/stable/esp32/api-reference/system/ota.html).
